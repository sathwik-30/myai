# Medha Conversational Brain

## Target behavior

Normal conversation is generated by a learned language model. The runtime must not contain a lookup table such as: if message equals hi.

### Runtime layers

1. Language model: understands and generates natural conversation.
2. Conversation context: supplies recent turns so follow-ups refer to the correct subject.
3. Memory: supplies user-specific facts when relevant.
4. Knowledge retrieval: grounds factual and technical answers.
5. Tools and policy: handle explicit actions and privileged operations.

## Model strategy

Medha uses a small pretrained causal instruction model as its conversational foundation. The model runs locally. Fine-tuning data lives under data/conversations/.

The existing custom MedhaDecoderLM remains available as a fallback during migration; it is not the primary conversational brain.

## Important separation

- Training data teaches general conversational behavior.
- Memory stores facts about a user.
- Knowledge stores books, PDFs, and other shared resources.
- Tools perform actions.

Do not bake personal secrets or user-specific facts into model weights.

## First local setup

From the repository root on Windows:

    python -m pip install -r requirements-brain.txt
    $env:MEDHA_BASE_MODEL="Qwen/Qwen2.5-0.5B-Instruct"
    python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000

The first model startup downloads the configured model to the local Hugging Face cache. Later starts use the local cached copy.

If the model cannot load, Medha falls back to the existing custom decoder and then to a minimal error response. It never silently calls a hosted API.
